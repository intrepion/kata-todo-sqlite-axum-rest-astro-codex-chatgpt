# Continuous integration

CI builds the existing Astro frontend and uses `cargo test --all-targets` to compile
Rust targets and run any available Rust tests. A successful run with zero tests is
compilation coverage, not behavioral coverage. No browser acceptance tests or
deployment are added. Rust and web jobs are independent so a broken baseline
remains visible instead of suppressing the other component's result.

Existing npm/pnpm lockfiles are installed in frozen mode. Existing Cargo.lock is
used with `--locked`; the repository without Cargo.lock resolves its declared
manifest instead. Missing modules, dependencies or invalid frontend configuration
are failures to fix in the application, not errors this workflow ignores.

The action lock is generated by official `github/gh-actions-lock` v0.4.1. After
changing workflow actions, run `gh actions-lock` and `gh actions-lock --verify`,
then commit workflow and lockfile changes together. `--verify-local` checks only
offline coverage. Repository-wide lockfile enforcement is not enabled.
